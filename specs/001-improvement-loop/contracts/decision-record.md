# Contract: 判断記録コメント

改善提案 Issue に投稿するコメントの書式。判断のたびに投稿し、最新のものを有効とする。

```markdown
## 判断記録
- 判断: 憲章の改定 / テンプレート・手順の修正 / 見送り / 重複 / 保留(追加情報待ち)
- 理由:
- 反映先: <!-- 対応予定の場合: 反映する Issue/PR、または「未着手」。重複の場合: 統合先 #N。見送りの場合: なし -->
- 判断日: YYYY-MM-DD
```

## ルール

- `判断` は上の 5 つのいずれか 1 つを書く。
- `理由` は空欄にしない(FR-006, SC-003)。見送りの場合は、どんな前提が変われば再検討するかも書く。
- 過去に見送った提案と同種の場合、理由に過去の提案番号と、前提が変わったかどうかを書く。
- コメントの投稿と同時に、[data-model.md](../data-model.md) の状態遷移に従ってラベルとクローズ状態を変更する。
- 反映 PR が中止された場合は、`判断: 保留(追加情報待ち)` または改めて判断した内容で新しい判断記録を投稿する。

## 憲章 VII との関係

- このコメントは提案ごとの「判断の経過」であり、憲章 VII の「決定記録」には当たらない。
- 標準を変更する判断(憲章の改定、テンプレート・手順の修正)は、反映コミットのメッセージに次を必ず書き、Git の中に残す。

```text
<type>: <変更の要約>

背景: <提案の問題点の要約>
判断理由: <判断記録の「理由」の要約>

Refs #N
```

## 検索

- 判断記録のある提案: `is:issue label:improvement "判断記録" in:comments`
